# Типовая небольшая правка проходит быстрее: CI гоняет только достижимые сценарии

## Why

Разбор задачи «обновление PHP» (2 ч 21 мин) показал, что заметную часть времени съедают этапы, не
добавляющие защиты: матрица Molecule из шестнадцати сценариев на PR, который правит только вики
или одну роль; отдельный PR на архивацию change после мержа кода; мутационная проверка роли при
правке значения параметра, где новой проверки нет.

## What Changes

- **CI выбирает сценарии по изменённым файлам** (`scripts/molecule-select.py`). PR, меняющий
  только вики, openspec или `*.md`, не гоняет ни одного; PR одной роли гоняет её сценарии и
  сценарии тех, кто её запускает или читает её переменные. Общие файлы (`galaxy.yml`,
  требования, workflow, `module_utils`, любой неназванный путь) выбирают все.
- **Полная матрица остаётся** на push в `main`, раз в неделю по расписанию и по ручному запуску.
- **Обязательные проверки не меняются**: `lint` идёт всегда, `molecule` по-прежнему репортится
  итоговым job'ом, который пропуск матрицы принимает только если выбор сам сообщил «сценариев
  нет».
- **Архивация change идёт в том же PR, что и код**, последним коммитом после ревью (правило
  владельца), а не отдельным PR после мержа.
- **Мутационная проверка роли обязательна только при добавлении или изменении проверки в
  `verify.yml`** (и сдвиге исходного состояния в `prepare.yml`); правка значения параметра без
  новой проверки её не требует.

## Не делает

- Не меняет защиту ветки `main` и имена обязательных проверок.
- Не убирает линт, вики-проверки, `secret-lint`, `names-lint` и юнит-тесты модулей из PR.
- Не пытается угадать связи, которых нет в тексте ролей: связь, названную только в голове
  автора, ловит полная матрица на `main`.
