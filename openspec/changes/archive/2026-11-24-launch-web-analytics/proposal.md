# Запуск сайта включает Cloudflare Web Analytics для всех посетителей

## Why

Cloudflare сам подставляет скрипт Web Analytics в HTML проксируемой зоны и сам заводит запись при
добавлении зоны, но новые зоны получают её в облегчённом виде (`lite: true`), и посетители из ЕС
скрипта не видят. Запрос владельца 24.11.2026: счётчик на всех сайтах потребителя и в сценарии
запуска, чтобы он ставился на новые. Для действующих сайтов записи уже переключены вручную;
сценарий запуска должен делать то же для новых, а не оставлять это на память.

## What Changes

- **Новый модуль `cloudflare_web_analytics`**: приводит запись зоны к `auto_install`, `enabled`,
  не `lite`, создаёт запись, если её нет, и читает обратно; принятое, но не сохранённое — отказ.
  Ищет запись по `zone_tag`, читает все страницы списка, аккаунт берёт из зоны, если он не назван.
  Без зоны только читает список аккаунта: так preflight проверяет право токена до первой записи.
- **Ключ `cloudflare_web_analytics` в `site_analytics`**, выключен по умолчанию: словарь передаётся
  потребителем целиком, поэтому отсутствие ключа значит «выключено», и сайты без него не меняются.
- **Шаг в `site_analytics`** (после `site_dns_records`, когда зона active) и вопрос в
  `site_preflight` со строкой отчёта `cloudflare web analytics`.
- Клиент Cloudflare получил обход страниц списка; фейк — записи Web Analytics.
- Версия 15.1.0 (новая возможность, прежнее поведение не меняется).

## Что не делается

Шаблоны сайтов не меняются — скрипт подставляет Cloudflare. Живые зоны роль не трогает: шаг
выполняется только в запуске сайта. Ревью в krot не проводится (решение владельца 23.11.2026).
