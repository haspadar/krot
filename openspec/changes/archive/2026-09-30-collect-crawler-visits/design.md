# Устройство сбора обходов

Правила перенесены из прежней PHP-реализации (классы `Colony\Crawlers\*` и
`Colony\BotRanges\*`); замеры, которыми каждое оплачено, лежат в её комментариях и повторены в
коде программы, где правило живёт. Паритет проверен прогоном одних и тех же входов через оба
кода (см. tasks.md).

## Строка лога

- **Одна регулярка по всей строке.** `[$time_local]` содержит пробел; разбиение по пробелам
  читает часовой пояс как адрес и печатает правдоподобные числа с кодом 0.
- Формат `time_first`: `[$time_local] $remote_addr - $host "$request" $status $body_bytes_sent
  "$referer" "$ua"` и необязательный хвост `… rt=$request_time`. Путь — второе слово запроса или
  весь запрос, если пробела нет.
- **`rt=` нет — не ноль.** Строка без поля не входит ни в сумму, ни в число замеров.
- **День — дата, как записал nginx**, со своим смещением, без пересчёта в UTC.
- Строка не по формату пропускается.
- ⚠️ **Новое:** файл, где неразобранных строк не меньше 20 и больше 1 % файла, — сбой: формат лога
  разошёлся с программой. Целиком — «пустой день» записал бы «никто не приходил»; наполовину (формат
  сменили посреди файла) — день, урезанный на сменившуюся часть, неотличимый от тихого. nginx
  пишет строки vhost'а в одном формате, у здорового файла таких строк нет; нижняя граница не даёт
  покраснеть маленькому сайту от пары странных строк. Цена: после смены формата файл, где есть
  оба, краснеет ночь-другую, пока дни после него не отмечены прочитанными. Первая редакция
  требовала «ни одной разобранной» — ревью показало, что так смена формата посреди файла молча
  урезает день.

## Обход файлов

- Файлы сайта: `<каталог>/<домен>-access.log*`, **от новых к старым** по номеру ротации (`.log`,
  `.log.1`, `.log.2.gz`, …), номер — числом, а не текстом.
- Точка возобновления — `max(day)` по `crawler_read` сайта. Строки старше неё пропускаются, сам
  день перечитывается целиком. Обход останавливается после файла, где встретилась строка старше
  точки: файл читается до конца, потому что nginx пишет в порядке завершения запросов.
- `.gz`: длина после распаковки сверяется с трейлером (4 байта, little-endian). Не совпала или
  файл не открылся — отказ.
- **Отказ обрывает обход, но дни из более свежих файлов, прочитанных до конца, сохраняются.** Не
  пишутся только дни из отказавшего файла — ни фигуры, ни маркер.
- Лога у сайта нет вовсе — строка в выводе, не сбой (закрытый сайт, где лог ещё не появился).

## Подсчёт

- `request_day` считается до любого решения о строке: запросы, `human`, 5xx, `rt`, `slow`
  (`rt > 1.0`), 5xx на `robots`, `sitemap`, `home`.
- Вердикты по порядку: семейство по UA (метки проекта — перед общими) → `impostor` для
  AI-семейств на запросе сканера → `-unverified` при ответе диапазонов «нет» (неизвестно — не
  помечает) → `-media` под `media_prefix`, если не impostor и не unverified. Без семейства —
  `human`.
- `crawler_section` — под тем же именем семейства, с суффиксами: сумма секций равна
  `crawler_day.requests`.
- `crawler_path` — только AI-читатели без суффиксов, путь без query, обрезка до 255.
- День заменяется целиком (`DELETE` + `INSERT` в одной транзакции), маркер `crawler_read` пишется
  и для дня, где были одни люди.
- Хранение — 14 месяцев, одна граница на все пять таблиц, число удалённых — сумма по всем.

## Разделы

Набор — данные проекта, один на проект. Порядок вычисления повторяет прежний код:

1. query и fragment отрезаются; `''` и `/` → `home`; `/robots.txt` → `robots`; префикс `/sitemap`
   → `sitemap`; `media_prefix` (с `/` в конце, иначе `/media` съел бы `/mediakit`) → `media`;
2. все правила в порядке объявления: префикс с непустым хвостом → раздел правила;
3. все правила снова: голый префикс (с `/` или без) → раздел правила при `bare: self`, иначе
   `other`;
4. `slice` (три сегмента, последний по шаблону) → его раздел;
5. глубже одного сегмента → `other`; файловый суффикс (с учётом регистра) → `other`; служебное
   слово (в нижнем регистре) → `other`;
6. единственный сегмент → `bare_segment` набора, если он задан, иначе `other`.

## Диапазоны

- Три ответа: адрес в диапазоне семейства — да; семейство публикует, адреса нет — нет; списка у
  семейства нет — неизвестно, и это не обвинение.
- Источники — общие данные программы (файл рядом с кодом), проект добавляет свои
  (`extra_range_sources`), например для своего монитора.
- Ответ источника принимается, если похожих на диапазон строк не меньше 80 %; адрес без маски —
  не диапазон; маска шире `/8` (`/16` для IPv6) отбрасывается, но в долю «похожих» входит. Ответ,
  где после этого не осталось ни одного диапазона, — отказ: принятый, он заменил бы вчерашний
  список пустым.
- Отказавший источник сохраняет вчерашние строки; строки источников, которых больше нет в списке,
  удаляются после прогона.
- Список, опубликованный больше 12 месяцев назад, называется в выводе.

## Решения, оставленные krot

- **`crawler_path` включается флагом** `ai_paths: true`, а не списком семейств: писать разрешено
  только AI-читателям без суффиксов, и список, заданный проектом, это правило обходил бы.
- **Порог мусорного файла** — см. «Строка лога».
- **Диапазоны — на проект**, в его базе: база проекта — единица, и роль не заводит общего
  хранилища машины. Цена — общий список тянется каждым проектом.
- **Имена** — роль `collecting`, программа `krot-collect`, учётка и схема `krot_collect`.

## Цена отдельной схемы

Потребитель, у которого Doctrine фильтрует схему `krot` (`schema_filter: '~^(?!krot\.)~'`),
увидит `krot_collect` в diff и предложит её удалить. Фильтр нужен шире —
`'~^(?!krot(_\w+)?\.)~'` — до первого применения роли на его базе. Это правка проекта; роль
записывает её предусловием в вики.
