# Роль indexing каждый день сохраняет число страниц в индексе Яндекса и Bing

## Why

Админка владельца рисует «В индексе» и «Не в индексе» по Google из выгрузок GSC, а для Яндекса и Bing
чисел нет: проект читает `InIndex` у Bing на лету без истории, историю Яндекса не читает никто. Правило
источников — проекты собирают, админка импортирует и к API поисковиков не ходит; роль `indexing` уже держит
ключи обоих движков и схему `krot_index` в базе проекта, так что числа ложатся рядом с отправками.

## What Changes

- **Таблица `krot_index.index_count`** (схема версии 2): `site`, `engine` (`yandex` | `bing`), `day` — ключ;
  `in_index`, `not_in_index` — nullable; `collected_at`. NULL — неизвестно, 0 — измеренный ноль.
  Повторный сбор перезаписывает день, а известное значение неизвестным не затирает.
- **Отдельный юнит на проект `krot-index-<проект>-counts`** со своим таймером раз в сутки: он только читает
  статистику, не тратит норму отправки, и красный сбор чисел не должен красить ночь отправки (и наоборот).
  Движки берутся из объявленных `engines` проекта: bing и yandex; ключи те же, что у отправки.
- **Bing** — `GetCrawlStats`, поле `InIndex`, ряд за ~29 дней одним запросом; дни датирует Bing.
  «Не в индексе» Bing не даёт — NULL.
- **Яндекс** — `search-urls/in-search/history` (страницы в поиске, точки на даты обновления выдачи),
  `in_index` только на даты точек; `not_in_index` — текущее `excluded_pages_count` из `summary` на день
  сбора: истории исключённых у API нет (`events/history` даёт потоки появилось/исключено, а не остаток).
  `HOST_NOT_LOADED` и `HOST_NOT_INDEXED` — «данных пока нет», не отказ.
- Программа принимает базу версии 1 для ночей отправки (роль другого проекта на машине могла обновить
  программу раньше); сбор чисел требует версию 2.

## Не делает

- Не выдаёт гранты читателю админки владельца: его роль и права выдаёт сама админка.
- Не восстанавливает историю исключённых Яндекса и не выводит остаток из потоков событий.
- Не применяется к машинам и не выпускает версию коллекции.
