# Переименование схемы `indexing` ждёт уже идущую ночь проекта

## Why

Прогон 7.0.0 переименовывает `krot` в `krot_index`, не глядя на юниты. Ночь, запущенная ещё
программой 6.x, пишет в `krot.*` с явным префиксом, каждый оператор отдельной транзакцией: после
`ALTER SCHEMA` её следующая запись падает. Страница уже отправлена движку, а в базе её нет — её
предложат снова, норма тратится на повтор, ночь красная. Нашло ревью одного из проектов
2026-09-30; сейчас от этого защищает только правило рунбука проекта «прогонять днём».

## What Changes

- **Перед переименованием роль ждёт, пока активные `krot-index-<проект>-*.service` этого
  проекта завершатся**, — только когда переименование предстоит. Не останавливает: оборванная
  ночь теряет больше, чем подождавший прогон.
- **Ждёт не дольше самой длинной ночи** (`indexing_timeouts` плюс 5 мин): дольше юнит не живёт —
  systemd снимает его по таймауту. Не дождалась — отказ с именами юнитов, до переименования.
- Гонки после ожидания нет: юнит, стартовавший позже, — уже программа 7.x (она ставится раньше
  цикла проектов), а она читает через `search_path` и переживает переименование посреди ночи.

## Не делает

- Не ждёт юниты других проектов: их базы этот прогон не переименовывает.
