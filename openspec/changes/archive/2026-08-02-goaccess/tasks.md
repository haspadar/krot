## Дефекты, найденные прогоном (не вычиткой)
- [x] **Пустой лог ронял всю сборку.** GoAccess не создаёт файл, когда нечего парсить, и `mv`
      падал, унося отчёты всех остальных сайтов. Проверка на существование файла
- [x] **`.html.tmp` молча не писался.** GoAccess выбирает формат вывода по расширению и для
      нераспознанного не пишет ничего — успешно, без единого слова. Временное имя теперь тоже
      оканчивается на `.html`
- [x] **Старые строки хоронили отчёт.** Не «пропускаются как невалидные», а бросают файл
      целиком: 119 старых строк против 3 новых давали `Format Errors` и ноль отчётов. Фильтр
      `grep '^\['` на входе
- [x] **`grep` при пустом логе ронял pipefail** — `|| true`, иначе сайт без трафика читался
      как сломанный отчёт
- [x] **Роль не была идемпотентной**: сборка с `changed_when: true` давала `changed` на каждом
      прогоне. Теперь строит только когда отчётов ещё нет — обновляет их таймер

## По ревью (codex)
- [x] **Отчёты снятых сайтов оставались доступны.** Убрали vhost — отчёт продолжал отдаваться,
      называя домен и его трафик всякому, кто помнит URL. Скрипт удаляет отчёты доменов,
      которых нет в списке. Проверено: подложенный `retired.example.html` убран, четыре
      настоящих не тронуты
- [x] **`--persist` пересчитывал живой лог на каждом прогоне.** Ревьюер был прав, я сперва
      ошибочно счёл замечание опровергнутым: мой первый тест подавал файл через stdin, где
      `log_path` = `STDIN`, и цифра не росла. Прогон настоящего скрипта показал 3 → 5 → 7 → 9
      за четыре сборки. Дедупликации строк у GoAccess нет вовсе, только `--keep-last` по дням.
      Persist убран, отчёт строится с нуля из всех логов на диске — после правки 3, 3, 3, 3
- [x] **Терялся час трафика в сутки.** Ротация ежедневная, сборка ежечасная: запросы между
      последней сборкой и ротацией оставались только в `.1`. Пересборка из всех логов, включая
      `.gz`, закрывает это заодно. Проверено: запрос только из ротированного файла попал в отчёт
- [x] **Недописанный отчёт лежал в раздаваемом каталоге** по предсказуемому пути, и `try_files`
      не отказывал в dotfile. Сборка вынесена в `.build/` внутри того же каталога — внутри,
      потому что `mv` атомарен только в пределах одной ФС, а роль не может полагаться на то,
      что `/var/www` и `/var/lib` на одной. Каталог закрыт в vhost. Проверено: `/.build/…` → 403

- [x] **Отчёт переживал свои логи.** Раз цифры теперь отражают только то, что на диске, отчёт
      сайта, чьи записи ротировались, показывал бы трафик, которого ни в одном логе уже нет.
      Удаляется. Тонкость, найденная прогоном: при чтении со stdin GoAccess пишет отчёт
      **всегда** — на пустом входе выдаёт страницу нулей, а не отсутствие файла, поэтому
      проверять надо число разбираемых строк, а не наличие результата

- [x] **Снятый сайт оставался доступен до таймера.** Прогон роли переписывал список, но сборку
      пропускал, если хоть один отчёт уже есть — снятый домен читался ещё до часа. Теперь
      изменение списка запускает сборку в том же прогоне. Проверено: подложенный
      `ghost.example.html` исчез сразу, `changed=0` при отсутствии изменений сохранился
- [x] **SC2045 от qlty**: итерация по выводу `ls` ломается на именах с пробелами. Заменено
      глобом с `sort -rV`; несовпавший глоб возвращает сам шаблон, поэтому каждый кандидат
      проверяется на читаемость

## Отдача переехала в busel (2026-08-02, после первой поставки)

Всё, что выше помечено про vhost, basic auth и туннель, **сделано и затем снято**. Причина не
техническая: через SSH-туннель отчёт не открыть с телефона, а это и есть основной сценарий.
В busel решение было принято раньше и записано в его `CLAUDE.md` — отчёт открывается роутом
`/traffic` внутри админки `busel.click` под её логином, без второго пароля и без поддомена в
публичном DNS. В krot это решение не перенесли, поэтому роль его не знала.

- [x] Сняты vhost, guard на loopback, обе проверки auth, хендлер reload и переменные
      `goaccess_listen_address` / `goaccess_listen_port` / `goaccess_auth_enabled`
- [x] Роль **удаляет** `/etc/nginx/conf.d/krot-goaccess.conf`, а не просто перестаёт его
      ставить: на развёрнутых машинах nginx иначе продолжил бы отдавать 8443 после обновления
- [x] Права отчётов `0644` → `0640` плюс `chgrp` в группу каталога. Каталог и раньше был закрыт
      `0750`, но защита держалась на одном рубеже вместо двух, а читать файлы теперь будет ещё и
      PHP-FPM
- [x] Группа читателя вынесена в `goaccess_reader_group` (по умолчанию `www-data`)
- [x] **`chgrp` из скрипта падал: `Operation not permitted`.** Сборщик работает под `goaccess`,
      который намеренно не состоит в `www-data`, а сменить группу файла на ту, в которой не
      состоишь, может только root — сборка валилась на первом отчёте целиком, не только права.
      Решено setgid-битом на каталоге: группу назначает ядро. Найдено прогоном
- [x] **Setgid на каталоге отчётов не помогал.** Файл собирается в `.build/` и наследует
      группу *его*, а `mv` группу не меняет. Каталог сборки пересоздаётся каждый прогон, чтобы
      наследовать бит и группу от родителя. Проверено: `www-data` читает, `nobody` — отказ
- [x] **Пересоздание `.build` открыло гонку.** Таймер и прогон роли могут совпасть (тем легче,
      что `Persistent=true` догоняет пропущенное), и второй сборщик снёс бы каталог под первым.
      `flock --nonblock` на каталоге отчётов; `--conflict-exit-code 0`, иначе systemd записал бы
      занятый замок как сбой юнита. Проверено: два одновременных прогона — оба 0, отчёты целы
- [ ] Роут `/traffic` — **на стороне busel**, не в этой задаче
- [ ] **Роль не подключена к `site.yml` busel** — она стоит на машине с ручного прогона, но
      плейбук её не знает: на новой машине её не будет. Строку добавлять в busel
