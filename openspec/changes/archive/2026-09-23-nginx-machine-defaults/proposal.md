# Настройки nginx, которых на машине может быть только одна копия, ставит роль

## Почему

На машину busel заезжает вторая сеть — gudok (`freeyourphone.de`). Её генератор портирован из
busel и пишет такой же общий файл в `/etc/nginx/conf.d/`. Два таких файла nginx не принимает —
проверено `nginx -t` на `nginx:alpine`, отказы по очереди:

1. `"real_ip_header" directive is duplicate`
2. `"real_ip_recursive" directive is duplicate`
3. `a duplicate default server for 0.0.0.0:80` (и то же для 443)

Уживаются только `log_format` с разными именами и повтор `set_real_ip_from`.

Эти директивы — свойство **машины**, а не сети: real-IP нужен всем сайтам за Cloudflare, сервер
по умолчанию бывает один на порт. Хозяин им нужен один на машину, и сети его знать не должны.

### Это переоткрывает решение 2026-07-31

Change `2026-07-31-deploy-and-preview-lock` убрал real-IP из роли и отдал генератору busel. Довод
был «два писателя на одну настройку разъезжаются» — и с одной сетью генератор был единственным
писателем. Со второй сетью писателей снова два, и тот же довод теперь указывает на krot.

Второй довод тогда — «генератор обновляет диапазоны CF при каждой генерации, а не раз в прогон
Ansible». Он остаётся в силе: устаревший `set_real_ip_from` не падает, а молча пишет в логи
адрес CDN. Поэтому роль берёт real-IP **вместе с таймером**, а не шаблоном, обновляемым прогоном.

Решение подтверждено владельцем 2026-09-23.

## Что меняется

Два независимых флага, оба выключены по умолчанию — роль остаётся безопасной на машине не за
Cloudflare и ничего не меняет, пока инвентарь не попросил:

- **`nginx_cloudflare_real_ip`** — `/etc/nginx/conf.d/krot-real-ip.conf`: `set_real_ip_from`
  по диапазонам CF, `real_ip_header CF-Connecting-IP`, `real_ip_recursive on`. Файл пишет
  **только** скрипт `krot-nginx-real-ip`; его зовут и роль, и суточный таймер. Скрипт никогда не
  оставляет пустой или половинный список (нужны оба семейства), проверяет `nginx -t` перед
  reload и при отказе возвращает прежний файл;
- **`nginx_default_server`** — `/etc/nginx/conf.d/krot-default-server.conf`: `listen 80
  default_server` и `listen 443 ssl http2 default_server`, оба `return 444`. Сертификат —
  самоподписанный snakeoil из пакета `ssl-cert`, а не сертификат одного из сайтов: роль не знает
  про сайты, а соединению, которое сейчас закроют, имя в сертификате безразлично.

Флаг выключен — роль убирает свой файл: выключатель должен выключать.

### Предпроверка: чужая копия — отказ до записи

Включив флаг, роль сначала ищет те же директивы в чужих файлах `conf.d/` и `sites-enabled/`. Нашла
— падает **до записи**, называя файлы. Без этого выкатка роли раньше правки генератора положила бы
`nginx -t`, а с ним и reload **всех** сайтов машины.

`set_real_ip_from` в чужом файле nginx принимает — но это второй писатель, ради устранения
которого всё и затеяно, поэтому он тоже отказ.

### Порядок выкатки на busel

1. krot: мерж и тег — на машине ничего не меняется, флаги выключены.
2. busel одним PR: убрать real-IP и серверы по умолчанию из `templates/nginx/shared.conf.twig`,
   поднять версию коллекции, включить оба флага в `recipients.yml`.
3. На машине: выкатить релиз busel, `recipient:nginx:generate` **без `--reload`** (урезанный
   файл на диске, живой nginx не перечитан), затем прогон krot — пишет свои файлы, `nginx -t`,
   reload. Живой nginx промежутка без real-IP не видит.

Проверка — по правилу `adult/CLAUDE.md`: побайтная сверка на машине и `nginx -T` до и после.

### Что остаётся сети

Общий файл сети — только её `log_format`, названный по сети (`busel`, `gudok`). Префикс `krot-`
в `conf.d/` занят ролью.

## Чего здесь нет

- **IPv6-слушателей по умолчанию** — у busel их нет и сейчас; добавлять поведение сверх переноса
  не будем, пока не видно vhost'ов на `[::]`.
- **Правки busel** — её делает отдельный PR в busel по согласованию с владельцем.
