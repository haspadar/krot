## Дефекты, найденные прогоном (не вычиткой)
- [x] **Пустой лог ронял всю сборку.** GoAccess не создаёт файл, когда нечего парсить, и `mv`
      падал, унося отчёты всех остальных сайтов. Проверка на существование файла
- [x] **`.html.tmp` молча не писался.** GoAccess выбирает формат вывода по расширению и для
      нераспознанного не пишет ничего — успешно, без единого слова. Временное имя теперь тоже
      оканчивается на `.html`
- [x] **Старые строки хоронили отчёт.** Не «пропускаются как невалидные», а бросают файл
      целиком: 119 старых строк против 3 новых давали `Format Errors` и ноль отчётов. Фильтр
      `grep '^\['` на входе
- [x] **`grep` при пустом логе ронял pipefail** — `|| true`, иначе сайт без трафика читался
      как сломанный отчёт
- [x] **Роль не была идемпотентной**: сборка с `changed_when: true` давала `changed` на каждом
      прогоне. Теперь строит только когда отчётов ещё нет — обновляет их таймер

## По ревью (codex)
- [x] **Отчёты снятых сайтов оставались доступны.** Убрали vhost — отчёт продолжал отдаваться,
      называя домен и его трафик всякому, кто помнит URL. Скрипт удаляет отчёты доменов,
      которых нет в списке. Проверено: подложенный `retired.example.html` убран, четыре
      настоящих не тронуты
- [x] **`--persist` пересчитывал живой лог на каждом прогоне.** Ревьюер был прав, я сперва
      ошибочно счёл замечание опровергнутым: мой первый тест подавал файл через stdin, где
      `log_path` = `STDIN`, и цифра не росла. Прогон настоящего скрипта показал 3 → 5 → 7 → 9
      за четыре сборки. Дедупликации строк у GoAccess нет вовсе, только `--keep-last` по дням.
      Persist убран, отчёт строится с нуля из всех логов на диске — после правки 3, 3, 3, 3
- [x] **Терялся час трафика в сутки.** Ротация ежедневная, сборка ежечасная: запросы между
      последней сборкой и ротацией оставались только в `.1`. Пересборка из всех логов, включая
      `.gz`, закрывает это заодно. Проверено: запрос только из ротированного файла попал в отчёт
- [x] **Недописанный отчёт лежал в раздаваемом каталоге** по предсказуемому пути, и `try_files`
      не отказывал в dotfile. Сборка вынесена в `.build/` внутри того же каталога — внутри,
      потому что `mv` атомарен только в пределах одной ФС, а роль не может полагаться на то,
      что `/var/www` и `/var/lib` на одной. Каталог закрыт в vhost. Проверено: `/.build/…` → 403

- [x] **Отчёт переживал свои логи.** Раз цифры теперь отражают только то, что на диске, отчёт
      сайта, чьи записи ротировались, показывал бы трафик, которого ни в одном логе уже нет.
      Удаляется. Тонкость, найденная прогоном: при чтении со stdin GoAccess пишет отчёт
      **всегда** — на пустом входе выдаёт страницу нулей, а не отсутствие файла, поэтому
      проверять надо число разбираемых строк, а не наличие результата
