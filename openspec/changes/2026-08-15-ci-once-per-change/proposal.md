# Proposal: CI платит за ответы, которые уже даны

## Why

В июле по сети закончилась общая на аккаунт квота минут Actions для приватных репозиториев — в
busel CI из-за этого простоял с июля по 2026-08-15 (там это разобрано в
`openspec/changes/2026-08-15-ci-runs-once-per-change`: квоту выел matilda, 507 прогонов за три
недели). Krot под раздачу не попал и выключен не был: `lint.yml` работает всё это время. Но
платит он из того же кошелька, и заплаченное разложено плохо.

Замерено по `gh run list` на 2026-08-15, окно 2026-07-30 … 2026-08-15 (17 дней):

| | |
|---|---|
| прогонов | **65** (64 success, 1 failure) |
| длительность | min 37s, **медиана 49s**, max 120s |
| суммарно | 3419s ≈ **57 минут** |
| по событию | `pull_request` **43**, `push` **22** |

Две статьи расхода, и обе платят за уже известный ответ:

**Прогон на `push: [main]` — 22 из 65 (34%).** Коммит проверен в PR и через несколько секунд
проверяется снова после мержа. Второй прогон отвечает на тот же вопрос про тот же код.

**Вытесняемые прогоны — 20 из 65 (31%).** 23 PR-ветки дали 43 прогона; у 11 веток прогонов
больше одного. Второй пуш обесценивает ответ первого — тот описывает коммит, которого в ветке
уже нет, — но прогон честно доходит до конца и списывается целиком. Лидеры: `feat/llm-wiki`,
`docs/openspec`, `chore/pg18`, `infra/deploy` — по 4 прогона на ветку.

Третья статья мельче и внутри самого прогона. Разбивка последнего (34 секунды полезной работы):

| | |
|---|---|
| `Install linters` (pip) | **8s** |
| `Install collections` (ansible-galaxy) | **8s** |
| `ansible-lint` | 15s |
| `yamllint`, `wiki-lint`, build, wiki-index | по 0–1s |

**16 секунд из 34 — установка зависимостей**, которые от прогона к прогону те же.

## What Changes

Три меры, каждая против посчитанной причины. Проверки не трогаются: они и не были проблемой.

**1. `concurrency` с `cancel-in-progress`.** Устаревший прогон отменяется новым пушем в ту же
ветку. Группировать по `ref`, а не по SHA: группа на SHA никогда не совпадёт между двумя
пушами и не отменит ничего. Экономия масштабируется с частотой коммитов — то есть ровно с тем,
что и создаёт расход.

**2. Убрать `push: [main]`.** Здесь krot расходится с busel, и расхождение существенное. Busel
эту меру ввёл, а потом **вернул `push: [main]` обратно** (коммит `6cac47c`): у него
`protected: false`, прямой коммит в main — зафиксированный дважды случай, а Deployer катит
main, поэтому непроверенный код доехал бы до прода.

В krot условие другое, проверено, а не предположено:

```
gh api repos/haspadar/krot/branches/main
-> protected: true, required status checks: ["lint"]
```

Main защищён и требует чек `lint`. Путь в main один — через PR, где прогон уже был. Мера,
небезопасная для busel, для krot безопасна именно потому, что защита включена. Обратная сторона
записывается прямо: **снятие защиты с main молча превращает эту экономию в дыру**, и решение
про защиту с этого момента связано с решением про CI.

`workflow_dispatch` остаётся — способ проверить main осознанно.

**3. Кеш pip и коллекций.** `actions/setup-python` с `cache: pip` и кеш каталога коллекций по
хешу `requirements.yml`. Экономит порядка 16 секунд из 34 на каждом оставшемся прогоне.

**`paths-ignore` — намеренно НЕ копируется из busel.** У busel в списке `wiki/**` и
`openspec/**`, и для него это верно: его CI их не читает. В krot **CI проверяет вики** —
`wiki-lint.py` и сверка `wiki/index/` с источниками. Скопировать список значит отключить
проверку вики ровно на тех правках, ради которых она заведена. `**.md` тоже не годится: страницы
вики — это `.md`. Единственный безопасный кандидат — `openspec/**`, но и он ловушка: change,
трогающий `openspec/` вместе с ролью, обязан проверяться, а `paths-ignore` смотрит на весь набор
файлов пуша. Экономия от него мала, риск неочевиден — не берём.

## Impact

- **Расход падает примерно вдвое.** 22 прогона push-в-main уходят целиком, 20 вытесняемых
  сокращаются до части своей длительности. По окну замера это 42 прогона из 65.
- **Освобождается бюджет под Molecule.** Change `2026-08-15-molecule-role-tests` добавляет
  прогон роли в контейнере — это минуты вместо секунд. Меры отсюда высвобождают больше, чем он
  займёт; порядок работ поэтому такой: сперва бюджет, потом расход.
- **Коммит в main перестаёт иметь свой прогон.** Запись «это состояние main проверено» теперь
  косвенная — через прогон PR. Пока main защищён, это то же самое состояние; если защиту снять,
  перестанет им быть.
- **Кеш может протухнуть** и дать «работает в CI, ломается у потребителя» — ключ вешается на
  хеш `requirements.yml`, чтобы смена зависимости кеш инвалидировала.
- **Проверок не убавилось ни одной.** Меняется, сколько раз задаётся один и тот же вопрос.

## Что сюда не входит

- **Возврат CI в busel** — сделан там же и уже влит (`b04867e`, `6cac47c`).
- **Molecule** — свой change; здесь только назван как потребитель освобождённого бюджета.
- **gitleaks.** В busel он есть, в krot его нет вовсе. Заводить сканер секретов — отдельное
  решение, а не побочный эффект правки расхода.
- **Защита main.** Здесь она только опора для меры 2; менять её настройки этот change не
  предлагает.
