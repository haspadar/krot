# Первый 403 IndexNow при верном файле-ключе — повтор, а не отказ

## Why

Первый прогон роли на проекте с новыми ключами (2026-09-29): IndexNow ответил 403 по всем трём
сайтам, юнит покраснел отказом по владению с починкой «ключ не тот». Ключ при этом был верный:
`prove()` прочитал файл секундой раньше, bingbot забрал его через секунду после POST с кодом 200,
а тот же POST минутой позже принят (200, у Яндекса 202). Ключ, который протокол видит впервые,
получает ответ раньше, чем его проверили.

Красный с починкой «ключ не тот» уводит смотреть на исправный файл — ровно то, от чего
`prove()` и был заведён.

Попутно та же ночь напечатала «5291 offered … 0/5291 sent» при `accepted = 5291` в
`krot.index_run`: у неопрашиваемого движка счёт отправленного брался до отправки.

## What Changes

- **403 после подтверждённого файла-ключа — пауза 60 секунд и один повтор отправки.** Второй 403
  — отказ по владению, как прежде; текст говорит, что файл был прочитан верным.
- **Счёт «sent» у неопрашиваемых движков — после записи принятого**, как у опрашиваемых счёт
  «answered» идёт после опроса.

## Не делает

- Не повторяет при 403, если файл не подтверждён: туда `prove()` не пускает — отказ раньше.
- Не повторяет больше одного раза: второй 403 минутой позже — уже не свежесть ключа.
