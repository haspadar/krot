# Хвосты 11.0.0: аудит без become, ранний отказ по правам, обрыв чтения sitemap

## Why

Первые раскатки 11.0.0 у двух потребителей (23.10.2026) оставили три хвоста.

1. Плейбук `haspadar.krot.search_console_access` у одного проекта запускается только с
   `-e ansible_become=false`: `ansible.cfg` потребителя включает `become` для всех плеев, а
   плейбук идёт на localhost, и модуль просит sudo на машине оператора. Плейбуку повышение прав
   не нужно ни для одного шага — он ходит только в Google. Требование флага — знание, которое
   каждый потребитель открывает заново.
2. Агент второго проекта отметил: preflight видит `grantable: false`, но запуск не
   останавливает, и нехватка прав будто бы выясняется лишь на `site_search` после деплоя.
   Нужно выяснить, что именно о правах ключей можно узнать до первой записи, и перенести
   проверку туда, если можно, — либо записать ограничение, не делая вид, что закрыто.
3. `krot_index` не переживает разовый обрыв чтения sitemap: с 29.09 по 22.10.2026 у одного
   проекта шестнадцать непрочитанных sitemap у двух движков, каждый раз на другом сайте, при
   том что origin отдавал файлы с 200, а повторные проходы читали всё. Строка журнала одна на
   все причины, и обрыв от сломанного sitemap отличали только по логу nginx.

Правила на будущее:

- плейбук коллекции, которому не нужна машина, сам выключает повышение прав и не зависит от
  `ansible.cfg` и инвентаря потребителя;
- всё, что запуск может узнать о ключах чтением, preflight узнаёт до первой записи;
- обрыв чтения sitemap повторяется один раз, ответ сайта — нет; отказ называет причину.

## What Changes

- **`search_console_access` задаёт `ansible_become: false` в переменных плея.** Запуск без
  лишних флагов работает и при `become = True` в `ansible.cfg` потребителя, и при
  `ansible_become: true` в его `group_vars/all`. Переменная, а не ключевое слово `become`:
  переменная инвентаря доходит до неявного localhost и перекрывает ключевое слово (замер на
  ansible-core 2.21). Тесты плейбука гоняются с включённым become из конфига и из инвентаря и
  заведомо неработающей программой повышения прав — возврат become в плейбук краснеет.
- **Preflight читает Search Console ключом запуска.** Разбор показал: `grantable: false` на
  запуске — не нехватка прав (запуск сам подтверждает домен TXT-записью ключом запуска до
  выдачи, и тот становится владельцем, даже если домен уже держит другой аккаунт), но ревью
  нашло настоящую дыру рядом: preflight звал `gsc_site` без `verify` и спрашивал только Site
  Verification, а Search Console API ключа запуска впервые трогался на подтверждении после
  деплоя. `gsc_site` с `verify` теперь читает список сайтов Search Console до подтверждения и в
  check mode; preflight зовёт его с `verify: true`. Подделка Google умеет выключить API одному
  ключу (`disabled_for`). Что видно только записью — в вике.
- Живой путь выдачи доказан (раскатка 23.10.2026: три домена `owned (granted now)`) — оговорка
  «проверено только на подделке» снимается.
- **`krot_index` повторяет чтение файла sitemap один раз при `web.Unreachable`** (таймаут,
  сброс, DNS) и не повторяет статус и «не XML». Строка журнала называет причину, адрес без
  query string. Граница прежняя: непрочитанный сайт красит юнит, остальные сайты ночи
  отправляются. Юниты получают `PYTHONUNBUFFERED=1`.
- Выпуск 11.0.1 (patch): новых входов и требований нет — preflight раньше останавливает запуск,
  который упал бы и так; в него же входит неотмеченная в CHANGELOG правка PR #111 (User-Agent
  проверки страницы монитора).

## Не делает

- Не переносит подтверждение домена и выдачу до деплоя: это запись, порядок запуска
  (`playbooks/site_launch.yml`) не меняется.
- Не меняет `gsc_access`: всё, что он может прочитать, он уже читает в check mode.
- Не повторяет запросы к поисковикам и не меняет таймаут сокета: повтор только у чтения sitemap.
