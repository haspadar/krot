# Роль cron снимает и перезаписывает только задачи своего проекта

## Why

Машина одна, а проектов на ней несколько, и каждый применяет `cron` из своего инвентаря со своим
`cron_jobs`. Роль при этом считала весь `krot-*` на машине своим:

- **снятие**: юнит `krot-*` с маркером роли, которого нет в `cron_jobs` этого прогона, снимался
  вместе с логом. Прогон проекта A останавливал и удалял задачи проекта B — молча, зелёным;
- **ротация**: `/etc/logrotate.d/krot-cron` один на машину и собирается из задач прогона. Прогон
  A стирал записи B, а прогон без файловых задач удалял файл целиком — логи B росли без ротации;
- **имя**: `krot-<задача>` без проекта. Два проекта с задачей `sitemap` перезаписывали юнит друг
  друга, а задача с именем чужого юнита без маркера (`cf-ranges` роли firewall) — и его.

Та же ошибка, что роль `indexing` исправила для своих юнитов
(`2026-09-29-retire-only-own-projects`); здесь у неё два лишних выхода — ротация и совпадение имён.

## What Changes

- **`cron_project` — обязательная переменная**, как только `cron_jobs` не пуст: `[a-z0-9]+`. В
  юнит пишется строка `# krot-cron-project=<проект>` рядом с прежним маркером.
- **Снимается только своё**: юнит с маркером и строкой своего проекта, которого нет в
  `cron_jobs`. Юнит другого проекта не трогается.
- **Юниты прежних версий** (маркер без проекта) не снимаются: их хозяина роль знать не может.
  Прогон называет их предупреждением; объявленный — перезаписывается и становится своим;
  ничей — снимается, только если назван в `cron_retired_jobs`.
- **Совпадение имён — отказ до изменений**: объявленная задача, чей юнит на машине принадлежит
  другому проекту или вовсе не роли `cron`.
- **Ротация — файл на проект**: `/etc/logrotate.d/krot-cron-<проект>`. Прежний общий
  `krot-cron` удаляется: он повторил бы записи нового файла, а на повторе logrotate перестаёт
  ротировать всю машину. Лог, уже записанный в файле другого проекта, — отказ до изменений по той
  же причине.
- **Мажорная версия**: инвентарь с `cron_jobs` без `cron_project` теперь отказ.

## Не делает

- Не переименовывает юниты (`krot-<задача>` остаётся): переименование на проде — остановка и
  запуск каждой задачи ради имени.
- Не снимает проект целиком по списку, как `indexing_retired_projects`: проект, уходящий с
  машины, прогоняет роль с пустым `cron_jobs`, и его юниты снимаются как свои.
