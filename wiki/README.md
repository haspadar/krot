# Krot

Ansible-коллекция `haspadar.krot` — переносимые роли, которыми провижинятся серверы сети. Крот
роет под сервисами и чинит «подземку» незаметно. Здесь всё, что нужно знать, чтобы с этим
работать.

Соседи по сети: **Matilda** (донор — парсит, нормализует, отдаёт профили по API) и **Busel**
(реципиенты — сайты, берущие профили из Matilda API). Krot держит машины обоих.

**Поднимаешь новый сервер — [порядок с нуля](runbooks/provision-a-machine.md).**

## Как добавить знание

Три способа, для разных моментов — выбирать между ними не нужно:

| Момент | Что делать |
|---|---|
| Узнал что-то, некогда думать куда | файл в [raw/](raw/README.md) — без правил, любой формат |
| Знаю тему, но не место | сказать агенту словами, он уложит |
| Знаю точное место | править страницу руками |

`raw/` существует ровно потому, что запись со структурой требует решения «куда это», а решения в
момент находки обычно нет. Инфраструктурное знание особенно ломкое: оно живёт в терминале и
пропадает вместе с сессией.

## Команды

```bash
python3 scripts/wiki-triage.py                  # разобрать raw/: что накопилось и куда ложится
python3 scripts/wiki-lint.py                    # проверить: ссылки, frontmatter, секреты
python3 scripts/wiki-index.py                   # пересобрать index/ из ролей, openspec и git
python3 scripts/wiki-after-archive.py <change>  # после архивации — что устарело
```

Зависимостей нет: только python3, который на машине с Ansible есть по определению.

**Первые две команды гоняются в CI** (`.github/workflows/lint.yml`): линтер валит сборку на битых
ссылках и секретах, а следом проверяется, что `index/` не разошёлся с источниками. Пересобирать
индекс перед push всё равно стоит — иначе PR краснеет на том, что чинится одной командой.

Проверка индекса смотрит `git status --porcelain`, а не `git diff --exit-code`: индекс, выпавший
из-под контроля версий, возвращается генератором как untracked-файл, которого `git diff` не видит
вовсе — проверка молча проходила бы ровно в том случае, когда индекса нет.

Две особенности этой проверки, обе стоили красного прогона в первый же день:

- **`fetch-depth: 0` в `actions/checkout` обязателен.** По умолчанию checkout делает shallow-клон
  (`depth=1`), а индекс восстанавливает номера PR из merge-коммитов — на неполной истории **все
  до единого** превращаются в прочерк, и пересобранный файл расходится с закоммиченным. Сборка
  при этом жалуется на устаревший индекс, хотя устарел клон.
- **Раннер живёт в UTC, автор — нет.** Прогон вечером по местному времени видит на календаре
  вчерашний день, и `verified` в индексе поехал бы назад. Поэтому дата в сгенерированном файле не
  уменьшается: генератор двигает её только вперёд.

`index/` **генерируется**, руками не править. Остальное пишется руками — правила в
[CONVENTIONS.md](CONVENTIONS.md).

## Чем это отличается от вики matilda и busel

Там страница объявляет `capabilities` и сверяется с `openspec/specs/`. **У krot этого нет:** он
описывает не поведение приложения, а машину, и его единица знания — роль. Поэтому во frontmatter
поле `roles`, а линтер сверяет его с папками в `roles/`.

Что делает роль — читается в ней самой: задачи и `defaults/main.yml` с умолчаниями. Вики отвечает
на другое — почему сделано именно так, что отказывает тихо, и какой ценой это выяснили.

## Чем читать

Обычный markdown в папке репозитория — ставить ничего не нужно.

- **PhpStorm** — `wiki/` в дереве проекта, ссылки кликаются. Поиск по всей вики — `Cmd+Shift+F` с
  областью «Directory: wiki».
- **GitHub** — читается прямо в репозитории, со ссылками.
- **Терминал** — `rg -l '<слово>' wiki/` быстрее любого интерфейса.
