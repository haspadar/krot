# Обновление PHP

**Ни один путь krot не обновляет PHP сам.** Роль ставит пакеты с `state: present`, и прогон на
машине, где PHP уже стоит, ничего не меняет, даже если в PPA ondrej лежит патч безопасности.
Unattended-upgrades из роли `common` берёт только security-источники Ubuntu, а PPA к ним не
относится (почему список источников именно такой, разобрано в
[Allowed-Origins дополняется](../research/apt-allowed-origins-appends.md)). Обновит PHP только то,
что проект добавил на машину сам. Поэтому, когда выходит патч PHP, его ставят прогоном роли с
`php_packages_state: latest`.

Умолчание остаётся `present` намеренно: пакет при установке сам перезапускает FPM, и прогон по
постороннему поводу не должен этого делать.

## Срочный патч

В плейбуке проекта, где роль подключена (у krot своего плейбука нет; тег — тот, под которым
проект подключил роль, если подключил):

```bash
ansible-playbook site.yml --tags php -e php_packages_state=latest
```

С `latest` роль поднимает **все установленные пакеты ветки**: `php<версия>`, `php<версия>-*`,
`libapache2-mod-php<версия>` и `libphp<версия>-*`, а не только перечисленные в `php_extensions`. Иначе на машине, где проект доставил своё расширение, ничего бы
не держалось: каждое расширение зависит от `php<версия>-common` строго той же версии, и apt
выбирал бы между обновлением пакета и его удалением. Ветку `php_version` прогон не меняет:
переход между минорными версиями — отдельная работа.

## До прогона: откат

**Прежней версии в индексе PPA может уже не быть.** В день патча 22.10.2026 `apt-cache madison`
показывал одну строку, новую версию, и откатиться «через apt» было нечем. Прежние пакеты
остаются в `/var/cache/apt/archives/`, если кеш не чистили. Их стоит скопировать в отдельный
каталог до прогона: `apt-get autoclean` удаляет пакеты, которых больше нет в индексе.

```bash
sudo mkdir -p /root/php-rollback-<старая версия>
sudo cp /var/cache/apt/archives/php<ветка>*_<старая версия>_*.deb /root/php-rollback-<старая версия>/
# откат: sudo apt-get install --allow-downgrades /root/php-rollback-<старая версия>/*.deb
```

Если в кеше пусто, пакеты ещё какое-то время лежат в пуле PPA по прямому адресу
(`https://ppa.launchpadcontent.net/ondrej/php/ubuntu/pool/main/p/php<ветка>/`). Launchpad удаляет
вытесненные версии не сразу, но и не держит их вечно.

Перед прогоном стоит снять коды ответа сайтов и список `systemctl --failed`: после прогона
сравнивать надо с этим, а не с ожиданием.

## После: чем доказывается, что патч дошёл

Нулевой код возврата и `changed` у задачи доказывают только, что пакеты распаковались. Что
работает новый код, доказывают:

| Проверка | Почему именно она |
|---|---|
| `php -v` и `php-fpm<ветка> -v` | CLI и FPM — разные бинари из разных пакетов |
| `readlink /proc/<pid>/exe` у мастера и воркеров FPM | процесс, не перезапущенный после обновления, указывает на `(deleted)` и продолжает исполнять старый код |
| `php-fpm<ветка> --test`, `nginx -t` | конфиги пакета могли разойтись с конфигами роли |
| коды ответа сайтов против снятых до прогона | 502 на всех сайтах при `active` у FPM — обычная картина сломанного сокета |
| `systemctl --failed` против снятого до прогона | упавшие задолго до прогона юниты не должны записываться на его счёт |

Пакет перезапускает FPM сам, двумя циклами stop/start подряд. Запросы, пришедшие в эти секунды,
обрываются (в nginx `connect() ... failed` и `Connection reset by peer`); это ожидаемо и
проверяется тем, что после перезапуска таких строк нет.

## Чего роль не касается

PHP внутри Docker-образов роль не видит и не обновляет: образ пересобирает проект, которому он
принадлежит. При патче их нужно перечислить отдельно.

Замер первого такого обновления — [патч PHP 22.10.2026](../research/2026-10-22-php-security-patch.md).
