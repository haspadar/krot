# Оповещения об отставании обновлений

Включаемая роль `updates_monitor` обслуживает одну машину. По умолчанию выключена:
потребитель выбирает существующий HTTPS-вхост и секрет. Внешний монитор роль не регистрирует.
Роль не создаёт вхост, сертификат, DNS или правила firewall.

## Как включить

В инвентаре машины задать `updates_monitor_enabled: true` и `updates_monitor_secret`
(случайный секрет от 32 символов). Вызвать роль, включить
`/etc/nginx/snippets/krot-updates.conf` внутри выбранного HTTPS `server` и проверить/reload nginx.
Потребитель настраивает чтение состояния самостоятельно; роль отдаёт сырые факты,
а выбор важных для доступности сервисов и причин остаётся у потребителя.

С версии 15.0.0 удалены переменные `updates_monitor_register`, `updates_monitor_api_key`,
`updates_monitor_api_url` и `updates_monitor_name` — убрать их из инвентаря.
Роль также перестала читать `updates_monitor_public_url`, но код потребителя может
использовать её для выбора HTTPS-вхоста: в таком случае оставить до изменения этого кода. Старые внешние мониторы роль не удаляет: их удаляют отдельно.
Роль не перезагружает машину и не перезапускает ожидающие обновления сервисы:
эти действия выполняются вручную.

## Что запускается

`krot-updates-collect.timer` включён и вызывает `krot-updates-collect.service` через две
минуты после загрузки, затем раз в час после предыдущего запуска. Команда —
`/usr/bin/python3 /usr/local/lib/krot-updates/check.py collect --grace 172800` от root.
Она обновляет APT-индексы (до трёх попыток по 120 секунд, паузы 5 и 15 секунд)
с отказом при недоступном источнике и читает разрешённые origins
из действующей конфигурации unattended-upgrades через её собственные функции.
Ни установка обновлений, ни перезапуск сервисов этой командой не выполняются.
Проверяются установленные пакеты с более новой версией в разрешённых origins, включая
held/kept-back, pinned и phased пакеты; blacklist не исключает долг из наблюдения.
Это контроль долга разрешённых origins, а не обещание, что unattended-upgrades
уже вправе поставить каждую версию на этой машине. При намеренной фазовой задержке
или pin оповещение требует решения оператора, а не автоматического снятия ограничения.

Возраст — время первого обнаружения непрерывно ожидающего пакета, а не дата публикации
в репозитории. При первом включении даётся 48 часов; новый кандидат того же пакета не
сбрасывает срок. Исчезнувший из списка пакет удаляется из истории. Установка и появление следующего обновления между двумя часовыми
замерами неразличимы с непрерывным ожиданием и сохраняют прежний возраст. История
`/var/lib/krot-updates/pending.json` доступна только root; удаление истории даёт новую
отсрочку, поэтому при диагностике её сохранять. Порог задаёт `updates_monitor_max_age`.

`needrestart -b -r l` только перечисляет ожидающие перезапуска сервисы. Любая строка
`NEEDRESTART-SVC` сразу переводит результат в отказ. Текстовый alert сохраняет эту семантику: reboot-required сам по себе не меняет его.
Сеансы пользователей в список сервисов не входят. JSON отдельно отдаёт признак
`/var/run/reboot-required`, строки `/var/run/reboot-required.pkgs` и `uname` текущего ядра.

`krot-updates-http.service` от nobody слушает только `127.0.0.1:9854` (порт меняется
`updates_monitor_port`). Запрос читает готовый `/var/lib/krot-updates/status.json`,
не запускает APT или needrestart. После `updates_monitor_stale_after` (три часа) результат
отказывает, даже если прежнее значение было `ok`. Текстовый ответ при отсутствующем, повреждённом или будущем
снимке тоже не даёт `ok`. Ошибка коллектора публикуется как `alert collection-failed`.

## Защита и эксплуатация

Точный путь — `/_health/updates/` плюс SHA-256 от `секрет:inventory_hostname`.
Секрет и путь скрыты из Ansible-вывода, snippet root:root 0640, access log выключен.
Потребитель должен исключить путь из CDN-кеширования и любых правил, меняющих тело ответа;
nginx и HTTP-читатель отдают `Cache-Control: no-store`. Запросы на угаданный общий путь
не попадают в location. Текстовый ответ содержит только `ok`, `alert updates=N services=N` либо
категорию отказа. Запрос с заголовком `Accept: application/json` на тот же точный
секретный путь возвращает `Content-Type: application/json` и `Vary: Accept`.
Нулевой/некорректный q и предпочтение text/plain или text/* сохраняют текстовый ответ;
без явного application/json (в том числе с одним */*) ответ текстовый:

```bash
curl --header 'Accept: application/json' 'https://<origin><secret-path>'
```

```json
{
  "collected_at": "2026-11-22T21:00:00Z",
  "stale": false,
  "collection_failed": false,
  "reboot_required": true,
  "reboot_packages": ["libc6", "linux-image-6.8.0-149-generic", "linux-base"],
  "running_kernel": "6.8.0-147-generic",
  "restart_services": ["containerd.service", "dbus.service", "docker.service"],
  "pending_updates": 0
}
```

Это иллюстрация контракта, не ответ боевой машины. `pending_updates` — число пакетов,
перешедших порог возраста (тот же N, что в текстовом alert), а не все доступные обновления.
`restart_services` содержит весь список `NEEDRESTART-SVC` без фильтрации.
Если маркера перезагрузки нет, `reboot_required=false`, `reboot_packages=[]`;
если маркер есть, но файла пакетов нет, список тоже пуст.
`collected_at` — время начала попытки сбора в UTC. Устаревший или будущий успешный
снимок сохраняет факты, но имеет `stale=true`. При ошибке сбора факты равны `null`,
`collection_failed=true`, время относится к неудачной попытке. Отсутствующий,
повреждённый или прежнего формата снимок не выдаётся за здоровый: факты `null`,
`collection_failed=true`; без достоверного времени также `collected_at=null`, `stale=true`.

Имена пакетов, сервисов и ядра с версии 15.0.0 передаются наружу по HTTP
только через секретный путь с JSON-заголовком. Нельзя публиковать URL или включать его в логи.
Локальный снимок доступен процессам машины (0644), история возраста остаётся root-only.
Администратор HTTPS-вхоста тоже видит секретный URL, как при паспорте сайта.

При ротации секрета повторить роль и проверить/reload nginx. До reload nginx
действует прежний путь. Смена `inventory_hostname` тоже меняет путь.

`updates_monitor_enabled: false` пропускает роль, не удаляет ранее установленные ресурсы.
Для прекращения наблюдения потребитель отдельно отключает таймер/HTTP-сервис
и убирает include с reload nginx.

Проверка: `molecule test -s updates_monitor` проверяет реальный сбор, закрытую историю,
живой HTTP/nginx, свежесть, таймер и идемпотентность. Чистую политику возраста и разбор
needrestart проверяют unit-тесты. Сценарий проверяет текстовый и JSON-ответ через реальный nginx на одном пути;
внешних API и мониторов не использует.

Origin PHP с коллекции 14.0.0 — `deb.sury.org:${distro_codename}` из
`53-krot-php-unattended`. Монитор читает эту политику при каждом сборе: отдельного
списка PPA в нём нет. После миграции роли PHP он учитывает Sury, а при выключении
разрешения PHP исключает его из наблюдения. Порядок миграции — [обновление PHP](php-updates.md).
