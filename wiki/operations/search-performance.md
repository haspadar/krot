# Сохранённая история поиска

Роль collecting управляет только заданиями ranges и crawl. Сбор поисковой статистики,
экспорт и ключи поискового API принадлежат приложению и больше не поставляются этой ролью.

## Существующие базы

Таблицы krot_collect.search_* и функция text_hash остаются на машине вместе с данными:
роль не удаляет их, не меняет структуру и не очищает историю. Это сохраняет историю и
возможность отката потребителя. Последующие применения schema.sql тоже их не затрагивают:
в файле больше нет DDL поисковых таблиц, DROP и очистки их строк.

Версия схемы остаётся 2: контракт таблиц обходов не изменился. Базы этой версии не требуют
миграции. На новой базе schema.sql создаёт только таблицы обходов и schema_version;
наличие версии 2 само по себе больше не означает наличие search_*. Читатель старой истории
должен проверять таблицы отдельно. Новые данные поиска и их схема — ответственность приложения.

При обновлении удаляются прежние Python-модули поиска и их кэш, а также отдельный файл
ключа объявленного проекта. Конфигурация проекта больше не содержит настроек поиска.
Юниты снятого задания удаляются существующим механизмом retirement только для проектов
текущего применения; чужие проекты на общей машине остаются нетронутыми.

Перед обновлением и после него сравни число строк search_day в каждой существующей базе.
При необходимости отдельно согласуй удаление истории с владельцем: применение collecting
такого разрешения не подразумевает.
