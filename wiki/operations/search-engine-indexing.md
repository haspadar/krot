# Ночная отправка страниц поисковикам

Роль `indexing` ставит программу `krot-index` и по юниту `krot-index-<проект>-<движок>` на
каждую пару: за ночь программа читает sitemap каждого сайта проекта по HTTP, отбирает страницы
по правилам движка, отдаёт их Google, Bing, Яндексу или IndexNow и пишет итог в схему `krot`
базы проекта. Нормы и грабли движков унаследованы из busel целиком — их источник и причины в
`design.md` change `2026-09-29-offer-pages-to-search-engines`.

## Что проект объявляет

`indexing_projects` в инвентаре, по ключу на проект (форма — `roles/indexing/defaults/main.yml`):
база, роль приложения `reader`, **явный** список `engines`, ключ каждого объявленного движка и
сайты с адресом sitemap.

- **Движки — список, а не наличие ключа.** Пустой lookup выключал бы движок молча, и ночь шла бы
  зелёной; здесь объявленный движок без ключа — отказ роли.
- **Один ключ — один проект.** Норма Google — Cloud-проекта сервисного аккаунта, норма Bing —
  ключа; роль сверяет `client_email`, ключ Bing и токен Яндекса между проектами машины.
- **Имя проекта — `[a-z0-9]+`**: оно читается обратно из имени юнита.

## Где что на машине

| Что | Где |
|---|---|
| программа | `/usr/local/lib/krot-index/krot_index/` |
| конфиг проекта (без ключей, читают все) | `/etc/krot-index/<проект>.json` |
| ключи (0600, `krot_index`) | `/etc/krot-index/<проект>.env`, ключ Google — `<проект>.google.json` |
| состояние | схема `krot` в базе проекта: `page_index`, `index_run`, `schema_version` |

Ключ Google — отдельным файлом, а в env-файле только путь: JSON сервисного аккаунта
многострочный, и `EnvironmentFile=` разобрал бы его по своим правилам.

## Схема в базе проекта

Схему создаёт и обновляет **только роль**, программа лишь сверяет версию и при расхождении
краснеет. Молча заведённая пустая схема на пересозданной базе забыла бы отправленное и потратила
бы норму на повторы — зелёным.

- Программа ходит учёткой `krot_index` по peer-сокету, без пароля; роль проверяет строку
  `pg_hba.conf`, а не предполагает её.
- Таблицы принадлежат `krot_index`: `schema.sql` применяется от её имени и только когда версия
  в базе не та, что в роли.
- `reader` получает `CONNECT` на базу (на случай, если у PUBLIC он отозван), `USAGE` и
  `SELECT`, а через `ALTER DEFAULT PRIVILEGES` — и на таблицы следующих версий. Писать
  приложение не может.
- **Чужую схему `krot` роль не перенимает.** Есть схема с этим именем другого владельца —
  отказ до изменений: `schema.sql` пошёл бы по таблицам, которых роль не писала.
- Все проверки — база, `reader`, чужая схема, строка peer — идут по всем проектам **до первой
  правки**; отказ по второму проекту не оставляет первый наполовину заведённым.
- ⚠️ **Doctrine проекта должен схему не видеть**: `schema_filter` с исключением `krot.` —
  иначе `doctrine:schema:update` предложит её удалить.

## Снятие: только своё

⚠️ **Каждый проект применяет роль из своего инвентаря, а машина одна** — у gudok в
`indexing_projects` только gudok, у busel только busel. Поэтому прогон снимает лишь то, что
знает:

- движок, выпавший из `engines` проекта **этого** прогона, — его юнит уходит;
- проект целиком — **только по имени в `indexing_retired_projects`**: его юниты и три файла.

Проект, которого прогон просто не знает, остаётся: это может быть чужой проект, и его ночи
перестали бы идти без красного — упавшего юнита не было бы, его не было бы вовсе. Цена правила —
проект, выпавший из инвентаря молча, стоит на машине, пока его не назовут в списке снятия.

Схема и строки снятого проекта остаются в его базе — это его история. В `/etc/krot-index` роль
трогает только файлы трёх своих имён (`<проект>.json`, `.env`, `.google.json`) — положенное
туда кем-то ещё остаётся.

## Как смотреть

```bash
systemctl list-timers 'krot-index-*'
journalctl -u krot-index-<проект>-<движок> -n 50
sudo -u postgres psql -d <база> -c "SELECT * FROM krot.index_run ORDER BY day DESC, site LIMIT 20"
```

Каждая строка вывода называет движок и сайт. **Красный юнит значит «чинить»**: ключ, владение,
схема, непрочитанный sitemap, ночь, где не принято ничего без названной причины. Кончившаяся
норма и заглушение — зелёные: красный, повторяющийся от календаря, перестают читать.

## Соседство с busel

busel пока отправляет сам — своими `krot-index-<движок>` от роли `cron`. Имена похожи, но роль
`indexing` снимает только юниты со своим маркером (`# krot-indexing-unit`), а `cron` — только
со своим. Перевод busel — по порядку из `proposal.md` change: снять старый таймер движка, потом
завести схему и перенести историю, и только потом объявить движок здесь.
