# Два FPM-пула на одном сокете не дают сервису стартовать

Замер от 2026-08-15, PHP 8.5 из ondrej PPA, Ubuntu 24.04, контейнер сценария `php`.

Пакет `php8.5-fpm` кладёт свой пул `pool.d/www.conf`, слушающий
`/run/php/php8.5-fpm.sock`. Роль `php` пишет собственный пул с тем же `listen`. **FPM
отказывается принимать такую конфигурацию целиком** — не игнорирует второй пул, не берёт
первый, а не стартует вовсе:

```console
# php-fpm8.5 --test
ERROR: [pool www] unable to set listen address as it's already used in another pool 'krot-test'
ERROR: failed to post process the configuration
ERROR: FPM initialization failed
```

systemd повторяет запуск пять раз и сдаётся:

```
php8.5-fpm.service: Main process exited, code=exited, status=78/CONFIG
php8.5-fpm.service: Start request repeated too quickly.
```

## Почему это не всплывало

При дефолтном `php_fpm_pool: www` роль пишет **в тот же файл**, `www.conf`, и просто
перезаписывает пакетный. Файл один — конфликта нет.

Дефект появляется ровно тогда, когда пул назван иначе, — то есть при любой настройке под
проект. Именно ради этого переменная и существует, так что «дефолт работает» здесь слабое
утешение: ломается настроенный случай, а не редкий.

## Замер обеих сторон

| Что в `pool.d/` | `php-fpm --test` | сервис |
|---|---|---|
| `www.conf` + `krot-test.conf` | ERROR, rc≠0 | не стартует |
| только `krot-test.conf` | `test is successful` | `active` |

Второй ряд получен удалением `www.conf` на живой машине — сервис поднялся сразу.

## Чем чинится

Роль отодвигает пакетный пул — **только если он действительно занимает её сокет**:

```yaml
- name: Look for a packaged pool on the socket this role's pool claims
  # grep по `listen = /run/php/php<ver>-fpm.sock`, exit 10 если не совпало

- name: Move it aside, since two pools cannot share one socket
  # mv www.conf -> www.conf.disabled, when: клеш найден
```

Два условия, и оба нужны:

- **`php_fpm_pool != "www"`** — при дефолтном имени роль сама пишет этот файл, и трогать его
  нечего.
- **совпадение `listen`** — первая версия правки проверяла только имя пула, и это оказалось
  дефектом. Замерено на ревью: рукописный `www.conf`, слушающий **другой** сокет, уживается с
  пулом роли без всякого конфликта (`--test` успешен, оба сокета обслуживаются), но условие по
  имени сносило его — вместе с сайтом, который на нём работал. Проверено обеими ветками:
  чужой файл на другом сокете уцелел, конфликтующий отодвинут.

**Переименование, а не удаление.** FPM инклюдит `pool.d/*.conf`, поэтому суффикс `.disabled`
выводит файл из конфигурации (замерено — `--test` проходит), и при этом файл, который роль не
писала, остаётся на машине.

## Чем ловится

Сценарий `molecule/php` задаёт `php_fpm_pool: krot-test` — не дефолт. На этом `converge` и
падал, пока роль не была исправлена. Родственная история —
[Allowed-Origins дополняется](apt-allowed-origins-appends.md): там тоже дефолтный путь был
здоров, а настроенный — нет.
